# Phase 3 — Git and GitHub

Development branch `codex/ion-phase-6-copilot`. The public 0.9.9 installer contains the accepted Phase 2.5 application.

## First checkpoint

| Action in Source Control | Behavior |
| --- | --- |
| Browse repository | Explicitly loads recent HEAD history, local branches, tags and remote names. Each result is bounded. Remote identities expose only recognized GitHub owner/repository pairs. |
| Compare branch or latest stash | Uses pinned commit IDs and rechecks references after reading. Branches can be ahead, behind or diverged. Stash compares against its own base and flags separately stored untracked content. |
| Create lightweight tag | Creates a new local tag at the reviewed commit and rejects an existing tag. |
| New branch | Creates a new local ref at the reviewed commit. The expected old ref must be absent. Ion also checks registered working copies for a matching unborn branch before creating a ref. Staged files, working files, current branch and unsaved buffers are preserved. |
| Line history | Reads the committed version of a tracked text file on request. Shows authors and commit subjects for bounded line ranges at the displayed HEAD commit. |
| Review conflict | Shows the common ancestor, ours or theirs from the index, distinguishing a missing side from an empty file. The user edits and stages the resolution. |
| Load from GitHub | Uses the officially installed GitHub CLI and system-keyring sign-in; reads the account, open pull requests and open issues on demand. Only reviewed GitHub links can open. A pull request can be prepared and submitted in the user's browser. |
| Clone public repository | Enter the public repository name and choose the parent in a native folder picker. Anonymous cloning is independent of the GitHub CLI sign-in used for private account data. Git makes a shallow, single-branch anonymous HTTPS checkout. A native no-replace move publishes it into a fresh named folder on the same volume as temporary storage. The user opens it explicitly. |

Git operations require the repository's existing trust review. Local browsing has no network side effects. GitHub's executable path, host, environment, subprocesses and output are bounded independently from local Git. The production build places local Git, hosted GitHub reads and clone code in on-demand main-process modules.

The GitHub panel now supports explicit sign-in through the official `gh auth login --web` device flow and explicit local sign-out through account-specific `gh auth logout`. Ion disables clipboard copying in the CLI, forwards only the bounded one-time device code to the renderer, and permits opening `https://github.com/login/device` only while that sign-in operation is active. ## Reviewed tracked-file discard — 27 November 2026

Source Control now offers **Discard unstaged changes** for one tracked, non-conflicted regular file at a time. A cancel-by-default native warning names the file, explains that its current staged version is retained, and states that the action cannot be undone from Ion. The operation restores from the index, leaving the staged content intact. It refuses untracked, conflicted, symlinked, non-regular and over-32-MiB files; it also refuses files with unsaved editor changes. Before writing, Ion checks the repository head/branch, the exact worktree and index status/object identities, and a SHA-256 fingerprint captured before confirmation. If the file changes while the confirmation is open, the discard is canceled.

## Reviewed in-app pull-request creation — 27 November 2026

Ion can now create a pull request for a repository loaded from the signed-in GitHub account. The user enters an existing head branch (optionally `owner:branch` for a fork), base branch, title, description and draft choice. Ion shows a review summary, then a native cancel-by-default confirmation before submitting the request through the officially installed `gh api` CLI to GitHub's REST create-pull-request endpoint. The remote head branch must already exist; this action never pushes commits or changes local files. Credentials remain in the GitHub CLI's OS credential flow and are never sent to the renderer. A successful response is checked against the requested repository, title, branches and draft state before its pull-request link becomes available.

The POST uses an isolated temporary `GH_CONFIG_DIR`, fixed `github.com` host and bounded request/response. PR fields are sent on stdin rather than command arguments. On an ambiguous network/timeout result Ion tells the user to reload the PR list before retrying, preventing blind duplicate submissions. GitHub documents that this endpoint can trigger notifications and return validation/rate-limit errors; the explicit native confirmation presents the target and warns that participants may be notified. [Create a pull request](https://docs.github.com/en/rest/pulls/pulls#create-a-pull-request) · [GitHub CLI `gh api`](https://cli.github.com/manual/gh_api).

Targeted macOS verification passed type checking, production build, **9 focused GitHub tests** (one live-keyring test skipped), and the headless Git browser journey including review-before-submit and created-link navigation. The suite verified stdin payloads, token-free renderer results, request validation, fixed host/method, response validation, no retry on uncertain outcomes and private scratch cleanup. No real GitHub PR was created. This increment has not had a native Windows run.

Phase 3 remains open: pull/push, authenticated Git remote transfer, different-tree branch switching/merge, stash writes/pop, restore/discard, and a three-way merge-resolution workflow still need independent safety designs and checks. Private cloning and in-app sign-in/sign-out administration also remain open. No public release, update-feed change, installed-app change or push of this development branch is claimed.

## Reviewed stash pop — 27 November 2026

Repository Browser can apply and remove the latest reviewed stash after a default-cancel native confirmation. The service requires an attached, clean, non-truncated repository, the same reviewed HEAD and branch, and the exact stash object shown by the browser. It rechecks repository and stash identities before execution. Modified editor buffers block the operation. Stash changes are restored to the working tree; the original staged/unstaged split is not reinstated. The Git command is limited to `stash pop stash@{0}`. Git conflicts are surfaced and the stash remains available. Git's `AUTO_MERGE` and `ORIG_HEAD` metadata are copied into the real common Git directory only when those targets are absent; existing conflicting metadata is preserved and the generated metadata is retained for recovery.

An initial real-Git test exposed that Git accepts a stash selector for `stash pop`, not a raw object ID. A second exposed that forcing `--index` can fail before applying a conflicted stash. The implementation now verifies the exact object and uses the standard non-`--index` pop path. Targeted macOS checks passed the complete focused Source Control suite (**22/22**), the comparison suite (**7/7**, including apply, cancel, dirty-editor refusal and conflict retention), TypeScript checking and production build. The headless Git browser journey reported its repository browsing and line-history assertions passed. Windows and a native desktop stash-pop journey remain unverified. Phase 3 remains open: merge, pull, push and broader restore/discard workflows still need safe implementations and checks.

## Reviewed branch merge and cached-branch pull — 27 November 2026

After comparing a local branch, Source Control offers **Review merge…** when the selected commit is ahead of or diverged from the current branch. For a cached remote-tracking branch, it offers **Review pull…** after an explicit fetch and comparison. Pulling the cached commit makes no network request; fetching remains a separate explicitly reviewed action. Both actions require a complete clean Git status and no modified editor buffers, then recheck the current branch/HEAD and selected ref OID after confirmation. They run only the reviewed OID with Git's built-in `ort` strategy, `--no-commit` and `--no-ff`; HEAD does not advance automatically. The staged result can be reviewed and committed in Ion. Conflicts remain visible in the existing conflict review UI and can be resolved, staged and committed as a two-parent merge. External merge drivers are refused for these operations, and Git hooks are disabled in the isolated configuration. Merge metadata is transferred back only after strict file checks; an existing `ORIG_HEAD`/`AUTO_MERGE` is replaced atomically only if it has not changed since review.

Targeted macOS verification passed Source Control (**22/22**), comparison (**7/7**), merge/pull (**2/2**), type checking, production build and the headless Git browser journey. Real Git fixtures cover cancel without changes, dirty-editor refusal, local merge and cached-remote pull, conflict visibility, staged conflict resolution, final two-parent commit, existing `ORIG_HEAD` replacement, and refusal of an external merge driver. The browser journey exercises the reviewed local merge and cached pull requests, and verifies these actions produce no hidden network traffic. A first typecheck caught the existing Git command allowlist's single-parent restriction; it now accepts only zero to two validated commit parents for Ion's `commit-tree` invocation. Native Windows and production Electron merge journeys remain open. Push remains unimplemented; pull requires the user to fetch a remote branch first.
